## 2. Fixed design

### 2.1 Fill flow (both adapters, element-targeted `fill` only)

```
kind = probe(el.path)                      # 'rich' = isContentEditable, 'field' otherwise; null = gone
if kind === null        -> StaleElementError('fill target gone before fill')
if kind === 'rich'      -> clear by keys + type value by key events      (NEW path)
else                    -> today's fast fill (locator.fill / select+Input.insertText)
readBack(el.path, value)                   # SKIPPED while a dialog is open, or under the read-back flag
if mismatch:
    clear by keys + type value by key events (the retry — same key path for BOTH kinds)
    readBack again
    if mismatch -> ActFailedError('fill read-back mismatch after key-event retry')
```

- `probe` and `readBack` are page evals built by NEW self-contained builders in
  `src/core/page-scripts.ts` (§ 3.1) — one source of truth for both adapters.
- Comparison is whitespace-normalized (`s.replace(/\s+/g,' ').trim()` on both
  sides), contenteditable reads `innerText`, input/textarea read `value`.
- The read-back comparator runs IN THE PAGE and returns only
  `{ok:boolean, reason?}` — the field text never returns to Node (§ 2.4).
- Retry typing for a plain field works because today's fast fills leave the
  field focused (PW fill focuses; CDP mouseClick focuses). The retry clears via
  SelectAll + Backspace KEY events, then types — trusted single-code-point
  input events, invisible to the corruption classes the fixture models.
- **AMENDMENT (2026-10-30, orchestrator-approved during WP-B, option (a)):**
  the read-back as first spec'd — an immediate eval after the act — RACES the
  fixture's (and the modeled Draft.js class's) async corruption, which lands
  via `setTimeout(0)`: the eval can be answered before that timer batch fires,
  compare the pristine text, return `ok`, skip the retry, and let the
  corruption land after the act resolved. Measured on the spec-verbatim build
  (`.build/r28b`, pre-amendment): `node scripts/run-tests.mjs --dist .build/r28b
  richtext-fill` = 9 pass / 3 fail (`r28 pw read-back failure`, `r28 cdp
  read-back retries` with #selfheal staying exactly 'CORRUPTED' and zero
  retry events, `r28 cdp read-back failure`), nondeterministically across runs
  of the same binary; `.calib/r28/act-debug.mjs` over the same build shows
  correct throw/retry/heal when the timer wins. Fix: `fillReadback` (§ 3.1) is
  ASYNC and awaits ONE `setTimeout(r, 0)` tick before reading — it flushes
  exactly the already-scheduled 0-delay corruption timers, deterministic, no
  wall-clock constant; both adapters evaluate with `awaitPromise: true`
  (cdp.ts `evalOnSession`, playwright.ts `evaluateOnPage`), so zero adapter
  change. This is production behavior for real Draft.js-class editors, not
  fixture accommodation.
- No new `Driver.act` return value for fills (void stays void). The
  check/uncheck flip and upload values are untouched. This keeps the
  `actRaced` propagation contract (root CLAUDE.md § Adapters) and the loop's
  `annotateLastOutcome` 'filled' annotation exactly as they are.

### 2.3 CDP per-char typing helper (new private method)

```
typeValue(sessionId, value):
  cdpKeyEvents('SelectAll')  down/up     # clear
  cdpKeyEvents('Backspace')  down/up
  for ch of value:
    ch === '\n'  -> cdpKeyEvents('Enter') down/up
    otherwise    -> Input.insertText { text: ch }
```

Used by BOTH the rich first attempt and the read-back retry. The playwright
mirror (§ 4.2 sketch) uses `keyboard.press(PW_KEYS.SelectAll)` +
`keyboard.press(PW_KEYS.Backspace)` + a `split('\n')` loop typing segments with
Enter presses between. Evidence probes (§ 5 WP-B step 3) confirm the fixture
behavior of both before green; if the PW probe shows `keyboard.type` mishandling
non-ASCII (the emoji test reds), the spec'd fallback is per-char
`rec.page.keyboard.insertText(ch)` for non-ASCII code points — one code point
per event, same safety property. This is a bounded contingency with a
deterministic trigger, not an open design choice.

  The three new failure messages are FIXED strings: `'fill target gone before

  retry'`, `'fill read-back evaluation failed'`. No value, no read-back text,

## 3. Contracts

### 3.1 New page-scripts builders (WP-B owns `src/core/page-scripts.ts`)

Per the purity contract (page-scripts.ts header, lines 3-11): each
`build*Expression` stringifies its backing function; every helper lives INSIDE
the function body.

```ts
export function buildFillKindExpression(path: string): string {
  return `(${fillKind.toString()})(${JSON.stringify(path)})`;
}
function fillKind(path: string): unknown {
  var el = document.querySelector(path);
  if (!el) return null;
  return el.isContentEditable ? 'rich' : 'field';
}

export function buildFillReadbackExpression(path: string, expected: string): string {
  return `(${fillReadback.toString()})(${JSON.stringify(path)}, ${JSON.stringify(expected)})`;
}
function fillReadback(path: string, expected: string): unknown {
  var el = document.querySelector(path);
  if (!el) return { ok: false, reason: 'gone' };
  function norm(s: string | null | undefined): string {
    return String(s == null ? '' : s).replace(/\s+/g, ' ').trim();
  }
  var cur = el.isContentEditable ? (el as HTMLElement).innerText : (el as HTMLInputElement).value;
  return norm(cur) === norm(expected) ? { ok: true } : { ok: false, reason: 'mismatch' };
}
```

(TS types inside the bodies follow the existing builders' `var el: Element | null`
style — mirror `buildVerifyExpression`'s backing function.)

Modeling notes (record, not to re-litigate):
- The rich rule models the observed Draft.js failure: ONE synthetic insertion
  event carrying more than one CODE POINT (not UTF-16 units — a lone emoji is
  1 code point and 2 UTF-16 units; `cps` counts code points) is applied twice.
  Both today's PW `locator.fill` (execCommand-style whole-string insert) and
  today's CDP whole-string `Input.insertText` trip it; real key events and
  per-char `Input.insertText` (1 cp per event) never do.
- `#selfheal` corrupts on a plain input's fast-fill paths: PW fill dispatches
  an UNTRUSTED input event (`!e.isTrusted` arm); CDP fill's `Input.insertText`
  is trusted but carries the whole string (`cps > 1` arm). Key-event typing is
  trusted and 1 cp — the read-back retry heals it.
- `#nokeys` swallows character keydowns, so it can ONLY be filled by the fast
  path — the pin that plain inputs keep today's fill (a build that routes plain
  inputs through key typing leaves it empty and reds).
- `#cursed` appends `X` on EVERY input event (deletes included): no fill
  strategy can land the exact value, so the act must FAIL — the
  never-silent-success pin.
- `window.__r28Events` is the mechanism log the tests assert against.
- Enumeration check: all four targets enumerate (role textbox / label-for);
  `elementNamed(driver, pageId, 'Post text' | 'Self heal' | 'No keys' | 'Cursed')`.
