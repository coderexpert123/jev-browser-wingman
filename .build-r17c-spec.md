# r17c spec: scroll growth waited out (t13), t14 task redesign

Intake: `.build-r17c-intake.md` (two r17 residual opens + one decision).
Branch `forced-handoff-0.3.0`, base HEAD `de78ea2`. Class C.

WP-1 (loop signal), WP-2 (adapter growth wait + Chrome tests) and WP-4 (bench t14)
are mutually independent and land in parallel. WP-3 (the committed KB mutant table)
lands after WP-1 + WP-2 because it pins their new test titles and flags. A verifier
wave runs after all land; the cloud validation runs after the local gates.

**Goal.** Two defects, closed by evidence:

1. **D-13 — t13 count evidence never fires live.** Every forced t13 call did ONE
   scroll and ended `fallback/no-progress` (telemetry: 18 records, all
   `no-progress` but 1 `target-uncertain`; the one scroll's annotation read
   `"no visible change"`, `countMetP` 0.26–0.32 every round). The 2/3 oracle
   passes came from the caller re-delegating 4–8 times. Root causes, both verified
   in code:
   - **The scroll signal is blind to scroll position.** A targetless scroll's
     `before`/`result` pair is `pageSignal(obs)` (loop.ts `outcomeSignal` →
     `annotateLastOutcome` targetless arm, ~477/~504): url + title +
     `shortHash(obs.text)` + `elements.length`. `window.scrollY` is not in it, so
     a wheel that moves the viewport but appends nothing yet reads *no visible
     change* — and the no-progress guard (`isNoProgress` targetless branch, ~583)
     then kills the second scroll round of every call.
   - **The append lands after the observation.** The scroll act is one wheel
     (playwright.ts ~381–389 / ~548–554, cdp.ts ~415–433 / ~561–577) with no wait
     for asynchronous DOM growth; `settle` returns at the first 3-poll stability
     of element-count + innerText-length (page-scripts.ts `settleProbe`, ~676),
     which is stable *before* jscroll's AJAX append lands. The next round's
     observe therefore grades a stale table (`repeatedGroups` short or without
     the `div.jscroll-added` group at all, which is below the ≥3 floor until the
     third chunk), `countMetP` grades low honestly, and the call ends.
2. **D-14 — t14's oracle is unsatisfiable as designed.** Enter submits/reloads
   (r17 end_states: `#result` empty, `focus=body`, all 5 cells). The task must
   press a key that does not submit.

Plus one decision: t10's residual one-login-end-per-cell (accept vs extend).

## Corrections (numbered; each names its basis)

- **C-1: The intake's "press the letter a" is not executable; t14 presses
  Escape.** `PRESS_KEYS` (src/contract/types.ts:13–15) is a fixed 11-key set —
  `Enter, Tab, ShiftTab, Escape, Space, Backspace, SelectAll, ArrowUp/Down/
  Left/Right` — and it is the exact Choice-id set of the Jev key question
  (src/core/questions.ts:71–85). Both adapters reject anything else
  (playwright.ts ~452 `ActFailedError('unsupported press key …')`; cdp.ts
  `cdpKeyEvents` maps only those keys). A letter key would end every attempt in
  `error/act-failed`. Escape is in the set, does not submit a form, does not
  move focus, and parses through `parseKeyPress` (`escape` is in `KEY_NAME_RE`,
  loop.ts ~144). Residual risk is the page's own handler shape — see Risk R1.
- **C-2: The intake's async-append hypothesis is half the root cause.** Even
  with the append fully landed, a viewport-moving scroll on this signal reads
  `no visible change`, because `window.scrollY` is not part of `pageSignal`
  (loop.ts ~463–467). The fix therefore has TWO legs (signal + wait); either
  alone still fails t13 in the other's window (leg 1 alone dies at-bottom
  pre-append; leg 2 alone never exits early on a moved viewport and never makes
  `hasScrollEvidence` true).
- **C-3: `settle` cannot be the wait.** `settleProbe`'s sig is element count +
  innerText length (page-scripts.ts ~676–679); it is stable *before* the append
  lands, so a longer settle budget mostly sleeps. The wait must compare a
  pre-act baseline against fresh probes of scroll position AND growth, which is
  a new helper, not a settle tweak.
- **C-4: E18's local pass is a fixture artifact — confirmed.**
  `fixtures/pages/chain-scroll.html` appends synchronously inside the scroll
  event handler (`window.addEventListener('scroll', add)`), so the post-act
  observation always sees the growth. The async case is untested today; E18b
  adds it with a wheel-armed `setTimeout` appender (in-page JS, runnable in
  local Chrome).
- **C-5: The count-advance bar stays 0.5 and gates BOTH arms.**
  `countAdvance` (loop.ts ~3099–3105 chain; ~2080–2091 legacy) requires
  `noulOf('count_met') >= THRESHOLDS.stepDoneWithEvidence (0.5)` AND
  (`hasScrollEvidence` OR the fresh obs's `repeatedGroups` meet N). This spec
  does NOT touch the bar or the OR shape; it makes both arms see honest inputs.
  Jev grading ≥0.5 on a fresh, visibly-met table is a cloud-verified assumption
  (Risk R3).
- **C-6: In-loop scrolls are always targetless.** `TARGETLESS_OPS` includes
  `scroll`/`scroll_up` and the loop always passes `elementId: null` for them
  (types.ts ~10); the element-id scroll form exists only for conformance rigs.
  The signal change below therefore needs only the targetless arm of
  `outcomeSignal`/`annotateLastOutcome`; the el-targeted arm is untouched.

## Decisions

- **D-A (D-13, leg 1 — signal):** add `scrollY` to the Observation as
  evidence-only, and give the two scroll verbs a scroll-specific targetless
  signal = `pageSignal(obs) + '\u0000scrollY:' + scrollY`. A moved viewport then
  reads `page changed`, `hasScrollEvidence` fires, and the no-progress guard
  stops killing the second scroll round. Guard semantics otherwise unchanged:
  an unchanged viewport with no growth still reads `no visible change` and
  still bounces (pinned by a new test).
- **D-B (D-13, leg 2 — wait):** after a `scroll`/`scroll_up` wheel, each real
  adapter polls a cheap in-page probe (scrollY + body-innerText-length +
  element-count) until it differs from the pre-act baseline or
  `SCROLL_GROWTH_WAIT_MS = 1500` expires (poll every `SCROLL_GROWTH_POLL_MS =
  200`). This is the bounded wait the intake allows: NO extra rounds, NO extra
  Jev asks — the cost is in-round wall time only, absorbed into `actMs`
  (telemetry note: scroll rounds' `act_ms` now includes up to 1.5 s of wait;
  do not read it as Jev latency). Genuinely stuck scrolls still burn the full
  1.5 s once, then the existing guard fires exactly as today.
- **D-C (D-14):** tasks.json t14 becomes "Click the input field, then press the
  Escape key." with the oracle on `#result` containing `escape` (case-folded)
  and the end_state expression unchanged (it carries focus, so the cloud
  evidence shows where the press landed). Assumption for cloud verification
  (stated, not locally provable — the-internet is not reachable from this
  machine): the key_presses handler records a non-Enter key pressed on the
  focused input as `You entered: Escape` without navigation. The r17 evidence
  is consistent: Enter-on-body left `#result` EMPTY, so the handler is not a
  document-level listener; an input-scoped keydown catches Escape.
- **D-D (t10 residual): ACCEPT, no code change.** The remaining 1 login end per
  cell fires on the final "click Login" step, whose text names no binding —
  suppression's binding arm correctly does not apply, and the end is an HONEST
  signal on a sign-in page (12 → 3 ends already banked the win). Extending
  suppression to "a credential binding existed earlier in the chain" would
  silence a real mid-chain login wall (expired session), which the caller and
  user genuinely need to see. The residual cost is one handoff per cell.
  Recorded here so no builder "fixes" it later.

## Risk register

- **R1 — the key_presses handler shape is unverified locally** (keydown vs
  keypress vs input-scoped; a `keypress` handler would not record Escape at
  all). Owner: WP-4 states the assumption; the cloud Stage-0 smoke cell is
  the only instrument that can see it (local Chrome cannot reach
  the-internet). Fallback decision named, NOT pre-built: extend `PRESS_KEYS`
  with the 26 letters (types.ts set, questions.ts ids + criteria text, both
  adapters' key maps, `KEY_NAME_RE`/`KEY_NAMES`, KB table) — a schema change
  requiring its own round.
- **R2 — `div.jscroll-added` could be crowded out of the top-5
  `repeatedGroups`** on the live page (top 5 by count desc, >= 3 floor). At
  10 chunks the group counts 10 and no competitor except `p.` (~20–40)
  approaches it, so both should make the cut — but this is cloud-verifiable
  only. Owner: cloud t13 evidence (per-round `countMetP` + `countEvidence`
  presence discriminates "group absent from state" from "Jev graded a present
  group low"). Fallback (new decision, not pre-built): raise the top-5 cap or
  prefer groups whose signature matches the clause's noun.
- **R3 — Jev's `count_met` honesty on a fresh table.** The advance bar (0.5)
  gates BOTH arms (C-5), so a low grade on a visibly-met table still blocks.
  The r17 0.26–0.32 grades are explained by staleness (C-2); if the cloud run
  shows fresh tables still graded < 0.5, that is a grading-calibration
  finding, not a mechanism defect — owner: r17c verifier escalates with the
  per-round telemetry; do NOT lower the bar in this round.
- **R4 — the scrollY signal weakens the stuck-scroll guard on scrollable
  pages** (every moved wheel now reads `page changed`, so a useless-scroll
  loop is caught only by budget-steps / the chain round cap, not by
  no-progress). Accepted trade — t13 requires sustained scrolling; the caps
  bound it. Owner: r17c decision; revisit only if a bench cell shows
  scroll-loops burning to budget. The unchanged-viewport pin (WP-1 test 3)
  keeps the non-scrollable guard intact.
- **R5 — test wall growth from the wait.** Every no-change scroll in a real
  adapter costs up to 1.5 s (conformance O9/O10, E18's early rounds are fast —
  they change). Bounded, owners: WP-2 runs the affected chunks; if a chunk

  lower them below 1500 without cloud evidence (the observed append landed

- **R6 — telemetry reading.** Scroll rounds' `act_ms` now includes up to
  1.5 s of growth wait; `settle_ms` does not. Anyone comparing
