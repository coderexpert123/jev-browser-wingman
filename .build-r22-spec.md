## F-1. Nav-shaped act-failed retry (mirrors the r21b observe amendment)

When an element-targeted act fails with a NAV-SHAPED error (the
`locator.click: Timeout ... scheduled navigations` family and evaluate-timeout
surfaces — reuse/extend the `NAV_SHAPED_OBS_ERROR_RE` pattern in loop.ts) and
the act was click-family, retry the act ONCE behind `PRE_CLICK_SETTLE_MS`
(4000) before ending `error/act-failed`. Bounds: one retry total per act;
deterministic failures (missing element, invalid ref) rethrow immediately —
the predicate is message-based like the observe amendment; a persistent nav
stall ends act-failed as today after the one retry. KB flag
`KB_ACT_NAV_RETRY` per the D-11 convention. Pins: (1) nav-shaped failure +
retry succeeds → the round proceeds (post-fix green, pre-fix red);
(2) persistent nav-shaped failure → exactly 2 sends then act-failed;
(3) non-nav failure (missing element) → 1 send, immediate act-failed.

## F-2. Resume-cheap: re-sent chains skip an already-post-action cursor

When a resume restores chain memory whose cursor clause previously ended
post-action (the clauseClicks/post-action state the memory already records)
AND the incoming chain is the same chain re-sent whole (same goal; the memory
match already proves it), the cursor advances past that clause to the next
one BEFORE the first ask, with a round-0 telemetry marker
(`resumeSkippedPostAction: true` — optional field, `!== undefined` guarded).
Safety: the skipped clause's action already ran (that is what post-action
records); the caller was told "continue with the steps after this one" and
re-sent everything as a convenience; skipping executes nothing new. The
goal-met screen still applies to every subsequently completed clause. Pins:
(1) post-action cursor + re-sent same chain → round 0 acts on the NEXT
clause's target, marker true; (2) cursor clause that ended for a NON-post-
action reason (e.g. target-uncertain) → no skip, existing behavior byte-for-
byte; (3) fresh chain (no memory) → unchanged.
