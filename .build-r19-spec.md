# r19 spec: close the gauntlet — sort-header enumeration (D-1), ondblclick (D-2), upload evidence (D-3), doctor both-sides reconcile (D-4), the bench log slice (D-5), and the publish protocol (M-2)

Class C. Serial dispatch — ONE builder at a time; file sets below are disjoint anyway.

**Goal.** Six items, five of them small code fixes with fail-first pins, plus the
publish-grade timing protocol:

1. **D-1** — t7-sort-table forced: the sort-header click never commits. Root cause is an
   enumeration gap, not a grader defect (C1 below): the-internet `/tables` sort headers are
   `<th>` elements wired by DataTables' JS event binding, and `page-scripts.ts` has no
   candidacy path for `th`. Fix: enumerate `th` as `columnheader`, plus a table-context
   field so the two identical "Last Name" headers (table1/table2) stay distinguishable.
2. **D-2** — t17-double-click: `ondblclick` attributes are invisible to enumeration. Fix:
   treat `ondblclick` exactly like `onclick` at all three detection sites.
3. **D-3** — t15-upload: upload acts carry no evidence. Fix: both adapters return
   `'uploaded'` from the upload op; the loop stores and consumes it exactly the way r17b's
   `KB_CHECK_FLIP` stores/consumes `'checked'`/`'unchecked'`.
4. **D-4** — doctor coexistence flake, third channel: the retry is asymmetric. Fix: on
   mismatch, re-fingerprint BOTH sides (up to 2 rounds); a transient cancels, a genuine
   mutation persists.
5. **D-5** — harness: single-call goal-met cells under-count handoffs. Root cause is a
   byte-offset-vs-char-offset slice bug (C2), not counter wiring. Fix: slice bytes, not
   characters.
6. **M-2** — the apples-to-apples publish protocol: one 68-cell interleaved invocation IS
   the publish run; per-task×route min/median/max; README block gains the environment line
   and the cost disclaimer.

Bounds honored: no new Jev question types, no new ops, no threshold moves, no
question-set changes. The gauntlet stays 17 tasks × 2 routes; only `repeats` changes
(1 → 2) for the publish run.

  BOTH parsers (`run.ts:659-663` and `handoffRecordsFromLog` at `bench/run.ts:519-523`)

  t9 record carries U+2026 (the clause quotes the page link "Example 2: Element rendered
  after the fact…"). The single-call correlation was a red herring — a cell with 1 call
  losing its first record reads as 0, a 4-call cell reads as 3 and nobody noticed.
  (Intake cite slip folded here: "r18 t16/B5" — no stage B5 existed; the stages were

- **D7 — doctor both-sides reconcile (D-4).**
  > **Amendment 2026-10-03 (WP-3, mid-build; the premise below was falsified by the
  > gate):** the both-sides reprobe does NOT preserve the guarantee — an attach-time
  > persistent write (`injectGlobal`, `closePageOnDetach`, and untested
  > `createContextOnAttach`) is absorbed into the re-read `before`, the fresh pair
  > matches, and the known-bad pins flip to PASS. Replaced rule: reconciliation is
  > gated on DEGRADED sides, classified by the sentinel's own marker (`dialogOpen`
  > true or any null detail field). Both sides healthy and differing → genuine
  > mutation, FAIL immediately with zero extra probes (the teeth). Before degraded +
  > after healthy → re-read BEFORE once, accept iff it matches the original after
  > (exact or url-only). Before healthy + after degraded → mirror (generalizes the
  > pre-r19 `onlyUrlsChanged` retry). Both degraded → FAIL, no retry (conservative:
  > a transient false FAIL is visible on re-run; a false PASS hides a write). The
  > reprobe signature is now `(side: 'before' | 'after') => Promise<ProbeFingerprint>`
  > and `maxRounds` is gone; WP-3 pin 3c's maxRounds case is superseded by
  > side-specific single-round pins.
  - `src/cli/coexistence-probe.ts` gains:
    ```ts
    export async function fingerprintsReconcile(
      before: ProbeFingerprint,
      after: ProbeFingerprint,
      reprobe: () => Promise<{ before: ProbeFingerprint; after: ProbeFingerprint }>,
      maxRounds = 2,
    ): Promise<{ match: boolean; after: ProbeFingerprint }>
    ```
    Semantics: `match: true` immediately when the pair matches exactly or
    `onlyUrlsChanged(before, after)` (the de78ea2 lenience is preserved, zero extra
    probes in the common case); otherwise up to `maxRounds` iterations of `await
    reprobe()`, accepting when the FRESH pair matches exactly or is url-only-different;
    `{ match: false }` after the rounds. A genuine page write persists in every re-read
    of `after`, so it still ends unmatched — the guarantee is unchanged. The helper
    returns `{ match: boolean; after: ProbeFingerprint }` where `after` is the freshest
    fingerprint seen, so the doctor's PASS message needs no extra call.
  - `src/cli/doctor.ts` 431-443: keep `before`/`after` as-is, then replace the lines
    436-438 retry + 439 comparison with one
    `const { match, after: freshAfter } = await fingerprintsReconcile(before, after,
    async () => ({ before: await fingerprint(conn), after: await fingerprint(conn) }));`
    and branch PASS/FAIL on `match`; the PASS message reads `freshAfter.pages.length`.

## Work packages (disjoint file ownership; serial dispatch)

Common rules for every WP: claim the file set with `pa claim` before the first edit and
`pa release` before committing (`pa run commit` refuses paths under your own active
claim, and active claims are foreign to the commit worker — release-then-commit is the
pattern). Commits go through `pa run commit` with ABSOLUTE wingman paths (repo-relative
resolves against the PA root and aborts). End every commit message with
`Co-Authored-By: Claude Code <noreply@anthropic.com>`. No package may stash, check out,
reset or clean a file it does not own; a gate blocked by another session's work is
reported, never cleared away. Scoped tests use the project's own entry point
`node scripts/run-tests.mjs --dist <dir> <basenames>` (basenames EXCLUDE `.test.js`);
the runner takes the build/test reservation itself — never bypass it. Every WP proves
its pins fail-first BEFORE the fix (run the new test against unmodified source, confirm
red, then fix), and proves each KB mutant flips its pin red, then restores (D-11 grep).
