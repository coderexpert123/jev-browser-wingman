# r18 spec: measurement rigor (M1), round-cost decomposition + warm Jev session (S1), the standing generality gauntlet (G1)

Intake: `.build-r18-intake.md`. Branch `forced-handoff-0.3.0`, base HEAD `7ec9045`.
Class C. Serial dispatch — ONE builder at a time (operator directive); file sets below are
disjoint anyway. No prototype exists; this spec is function-level edit lists.

**Goal.** Three workstreams, all bounded:

1. **M1** — bench-only measurement upgrades: raw tokens in every report, spread reporting
   (min/median/max), and the interleaved schedule *validated as already-existing code*, not built.
2. **S1** — the round-cost decomposition made first-class (cold/warm Jev split, per-phase sums,
   per-round outcome classes), plus ONE bounded speed mechanism: a warm HTTP session in
   `jev-client.ts`. The observation cache is rejected on already-measured data (C3).
3. **G1** — the gauntlet as a standing 18-cell invocation: t9 + t10–t14 + three new tasks
   (upload / hover / dblclick — op coverage that is zero today), iframe and shadow-interior
   documented as verified boundaries with pin tests.

Constraint honored throughout: no new Jev questions, no verdict-bar changes, no t13/r15-mechanics
regressions, no policy/gate work.

## Corrections to the intake (numbered, code-verified)

- **C1: the interleaved schedule already exists in code; "Phase A then Phase B" is an invocation
  convention, not a property of `bench/run.ts`.** The schedule loop nests route INNERMOST —
  `bench/run.ts:843-846`: `for (repeat) → for (task of tasks) → for (route of app.routes)`. One
  invocation with `--routes playwright,forced --repeats 5 --tasks t9-long-chain` already produces
  A1,B1,A2,B2,… per task. Past rounds measured routes in SEPARATE invocations; that practice, not
  the code, created the load covariance M1-2 targets. **No `--interleave` flag ships.** The fix is
  procedural: the validation plan (WP-4) mandates route-vs-route comparisons in ONE invocation, and
  the new reporter prints the per-cell schedule order so the interleaving is auditable.
- **C2: the loop cannot see inside iframes or shadow roots — verified, so (b) and (c) of G1 are
  boundary-documentation tasks, and the "2-3 new tasks" quota is filled with two op-coverage tasks
  instead.** `buildEnumerateExpression`'s `enumerate` walks `document.querySelectorAll('*')` of the

  (`page-scripts.ts:484,646,671`); both adapters' act paths resolve `el.path` the same way. The
  ONLY iframe contact in the file is `CAPTCHA_RE` scanning `iframe[src]` attributes
  (`page-scripts.ts:396-402`). No `shadowRoot` traversal exists anywhere. An iframe-interior or
  shadow-interior element is invisible to the element table and unactable. The intake's own
  fallback for (b) ("the task becomes the documented boundary") is applied to (c) as well — its
  "element table through shadow roots" phrasing presupposed a capability that does not exist.
  Replacement tasks: t16 (hover op, zero bench coverage) and t17 (dblclick op, zero bench coverage),
  both deterministic local fixtures. Boundary fixtures + pin tests still ship (WP-3) so the future
  capability round starts from a committed artifact and a loud tripwire.
- **C3: the S1-2 "observe dominates?" question is already answered by r17c data — the observation

## Design decisions (exact literals)

- **D1 — Schedule:** no code change (C1). The gauntlet is ONE invocation with both routes.
- **D2 — `wingman_phases` extension (bench/run.ts).** The per-round timing instrumentation ALREADY
  EXISTS in `src/core/loop.ts` (`observeTimed` and the act/settle/ask timers, `PhaseRound` at
  `loop.ts:1618-1642`, shape pinned by `tests/loop.test.ts` "log record carries the phases
  breakdown"). S1's decomposition is therefore a bench-side REPORTING change plus one new
  loop-side telemetry field (D3). `aggregatePhases` (new, exported, pure) replaces the inline
  aggregation at `bench/run.ts:504-562` and returns, alongside the five existing fields,
  exactly these new fields:
  - `jev_first_ms`: median of `jevMs` over rounds that were index 0 WITHIN their own call's
    `phases.rounds` (the per-call cold round);
  - `jev_rest_ms`: median of `jevMs` over all other rounds;
  - `observe_sum_ms`, `jev_sum_ms`, `act_sum_ms`, `settle_sum_ms`: sums over all rounds, rounded;
  - `round_kinds`: `{act, advance, wait, bounce, done, error, other}` counts from the rounds'
    `kind` field (below). `median()` of an empty set stays 0 (existing helper semantics); a legend
    line in the reporter says `first/rest medians are 0 when the bucket is empty`.
  Existing median fields (`observe_ms`, `jev_ms`, `act_ms`, `settle_ms`, `attach_ms`,
  `first_observe_ms`, `rounds`) keep their semantics unchanged. `HARNESS_VERSION` 2 → 3
  (bench/run.ts:158; verified: no external consumer pins 2 — `wingman_phases` and
  `HARNESS_VERSION` appear nowhere outside `bench/run.ts`).
- **D3 — per-round outcome class (`PhaseRound.kind`).** New optional field on `PhaseRound`
  (`src/contract/types.ts` + the local `type PhaseRound` at `loop.ts:1618`), closed enum:
  `'act' | 'advance' | 'wait' | 'bounce' | 'done' | 'error'`. Assignment precedence — explicit
  first, terminal last:
  1. The shared act tail and `runTokenAction`, after the act resolves: `cur.kind = 'wait'` when
     the executed verb is `wait`, else `'act'`. The round-top dialog-answer site (r17 D5) sets
     `'act'`.
  2. `applyChainEarly`'s advance branch (where `chain.cursor += 1`, `loop.ts:3250`): sets
     `bucket.kind = 'advance'` — `bucket` is the round.
  3. `mk()` (`loop.ts:1715`) sets `cur.kind ??= kindForResult(status)` — never overwrites an
     explicit 1/2 assignment, so a round that acts AND ends done reads `'act'`.
     `kindForResult` (new, exported, pure, module-level): `done → 'done'`; `error`, `login →
     'error'`; `fallback`, `ambiguous`, `blocked`, `needs_confirmation → 'bounce'`.
  4. The two entry non-commit retry sites (`entryPending` + `goal-met`/`no-action` →
     `retried = true; continue`, `loop.ts:3592-3607`) set `cur.kind = 'bounce'` before the
     continue.
  Guard discipline per the standing gotcha: only assign when the site knows the value; a round
  that somehow exits with no kind simply lacks the key (bench buckets it `other`). Never log
  anything but the enum value.
- **D4 — warm Jev session (jev-client.ts).** Add the `undici` dependency (`npm install undici@7`;
  record the resolved version in the build report). In `src/core/jev-client.ts`: a module-level
  lazily-created shared `new Agent({ keepAliveTimeout: 55_000 })` from `undici`, created on first
  use; `createDefaultAsk` attaches it as `dispatcher` in the fetch init ONLY when `opts.fetchFn`
  was NOT supplied (the `fetchFn: fetch` form reproduces today's behavior exactly — this is also
  the A/B arm of the direct probe). No change to: `MAX_ATTEMPTS`, the AbortController-per-attempt
  timeout structure, the 429/5xx retry ladder, `parseJevAnswers`, or the returned `JevResult`
  shape. `opts.fetchFn` callers (every existing test, the stub) are bit-for-bit unaffected. The
  change propagates to all three default-ask wirings automatically (`src/lib.ts:64`,
  `src/cli/doctor.ts:586`, `src/cli/with-chrome.ts:315` — verified). TypeScript: the dispatcher
  key needs a cast (`init as RequestInit & { dispatcher?: unknown }`).
- **D5 — rejected this round, with reasons on record:**
  - Observation cache keyed on the settle sig — rejected per C3 (~2% ceiling).
  - Settle fast-path (fewer than 3 stable polls when the sig matches a pre-act baseline) —
    rejected: saves ≤ ~130 ms/round against a caller-turn wall of ~3.4 s/round (2026-09-29 cells:
    148–600 s over 43–147 rounds), i.e. ~2–4% of wall, for a behavior change to the stability
    invariant that t6/t13-style pages depend on. Revisit only if the post-D4 decomposition still
    shows settle as the dominant loop-side term AND round counts stay high.
  - Pre-ask deterministic advance (skipping the per-clause advance ask when history evidence
    alone would satisfy rule 3) — rejected: it changes verdict-relevant semantics (today's
    click/nav evidence branches still read Jev's `step_done` noul); adjacent to the excluded
    "t9 verdict-bar" scope. The `round_kinds` tally will QUANTIFY the advance-round share so the
    next round can decide with numbers.
- **D6 — the gauntlet (standing regression suite).** One invocation:
  tasks t9-long-chain + t10-saucedemo-checkout + t11-todomvc-spa + t12-js-confirm-dialog +
  t13-infinite-scroll + t14-key-press + t15-file-upload + t16-hover-reveal + t17-double-click,
  routes `playwright,forced`, repeats 1 → 18 cells, interleaved by construction (C1),
  `--purpose measure` (it becomes the README block via readme-bench `--write`), env
  `BENCH_GATE_OFF=1 BENCH_POLICY_OFF=1`, `--cap-usd 4` with `--phase-cap-usd = ledger + 4`.
  Every future optimization claim runs this before landing (the quality guard), reported as one
  table per route: task, ok, wall, usd.
- **D7 — new tasks and fixtures.** Exact file contents in WP-3. All goals single-line ASCII
  (win32 cmd spawn constraint), all oracles single expressions. t15's value binding is
  `@REPO@/fixtures/files/sample-upload.txt`, expanded by the bench harness (D8) into a
  forward-slash absolute path — `isPathLike` (`src/core/withhold.ts:19-26`) accepts
  `^[A-Za-z]:[\\/]`, so `D:/...` qualifies and `upload` is offered (`questions.ts:135-143`).
  File CONTENTS never reach Jev: the file question's criteria are binding names + `none`
  (`FILE_EXTRA`, `questions.ts:101-103`); the path is resolved from `values` at act time
  (`loop.ts:2315-2331`, `playwright.ts:589-594` `setInputFiles(value)`).
- **D8 — `@REPO@` expansion (bench/run.ts).** New exported pure helper
  `expandTaskValuePlaceholders(tasks: BenchTask[], repoRoot: string): BenchTask[]`: for every
  task value, a leading `@REPO@` is replaced by `repoRoot` with backslashes folded to forward
  slashes; anything else passes through. Applied once in `runBench` immediately after
  `readTasks()`. The forward-slash choice avoids the win32 cmd backslash-before-quote trap in the
  spawned prompt (values already ride with spaces today, e.g. t3's `wingman bench`).
- **D9 — the reporter (bench/report.ts, new).** `node dist/bench/report.js <results.json>`
  (positional file; missing file → stderr + exit 2; entry guard same pattern as run.ts). Output,
  exact line templates (numbers: wall_s 1 decimal; usd as recorded; tokens integers):

  ```
  BENCH REPORT <fileName> purpose=<p> model=<m> harness=<v> aborted=<a> total_usd=<n> runs=<n>
  cell <task> <route> ok=<true|false> wall_s=<n> usd=<n> llm_in=<n> llm_out=<n> llm_cache_read=<n> llm_cache_write=<n> ts_calls=<n> ts_in=<n> ts_out=<n> fallbacks=<n> rounds=<n>
  route <name> n=<n> ok=<k>/<n> wall_s min=<n> med=<n> max=<n> usd min=<n> med=<n> max=<n>
  phases <task>/<route> attach=<n> first_observe=<n> observe=<n>+<n> jev=<n>+<n> jev first/rest=<n>/<n> act=<n>+<n> settle=<n>+<n> kinds act=<n> advance=<n> wait=<n> bounce=<n> done=<n> error=<n> other=<n>
  legend: cell lines carry RAW tokens (no price table); route min/med/max is the spread convention; phases lines med+sum, first/rest medians are 0 when the bucket is empty
  ```

  One `cell` line per run in file order; `route` lines only for routes present; `phases` lines
  only where `wingman_phases` is non-null. `ok=true|false` literal; `fallbacks` =
  `wingman.fallback`; `rounds` = `wingman_phases.rounds` when present else 0.

## Work packages (disjoint file ownership; serial dispatch)

Common rules for every WP: claim the file set with `pa claim` before the first edit and `pa
release` before committing (`pa run commit` refuses paths under your own active claim, and active
claims are foreign to the commit worker — the release-then-commit pair is the pattern). Commits go
through `pa run commit` with ABSOLUTE wingman paths (repo-relative resolves against the PA root and
aborts). End every commit message with `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
No package may stash, check out, reset or clean a file it does not own; a gate blocked by another
session's work is reported, never cleared away. Scoped test runs use the project's own entry point
`node scripts/run-tests.mjs --dist <dir> <basenames>` (basenames EXCLUDE `.test.js`); they never
bypass the build/test reservation — the runner takes it itself.
